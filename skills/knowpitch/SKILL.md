# KnowPitch — 阵型学习法

> **Put your knowledge on the pitch.**
>
> （把你的知识放上球场）

## 适用边界

✅ **适合：** 系统学习、知识梳理、备考复习、教学准备、概念深度理解

❌ **不适合：** 快速问答、情感咨询、精确数据分析、代码调试、纯事实查询

## 前置条件



* Python 3.8+（用于生成阵型图 SVG）

* 主题必须是 "知识类"（有明确概念体系），非情感 / 观点类

* 如需外部事实，先检索 / 读资料，确保知识点有来源、不编造

## 核心思维模式

> 排阵型前先问自己：
> **这个主题的 "门将" 是什么？**
>
> （最底层、丢了就全崩的基础）
> **这个主题的 "前锋" 是什么？**
>
> （最终要回答的核心结论）
> **中间的 "中场" 如何把基础变成结论？**
>
> （机制 / 方法 / 思想）

## 这个技能是什么

把任何知识领域当作**一支足球队**来理解：知识点是球员，按职能排进 4-3-3、4-2-3-1 等阵型，

再配一个主教练（一句话核心思想）、一个门将（底线基础）和替补席（进阶知识点）。

每个 "球员" 都用 ELI5 的方式讲成大白话。最后交付：**阵型图（SVG）+ 球员卡 + 教练战术板**。

它内化了 ELI5 技能的内核，因此所有讲解遵循：

> **假设零背景，不是零智商（assume zero background, not zero intelligence）**
> 用 5 岁小孩也能懂的大白话 + 日常类比，但不牺牲准确性。
> 每个专业词第一次出现时，紧跟一句大白话解释。
> 短句、短段、口语化；先讲 "它是干嘛的"，再讲 "怎么做到"，最后讲 "为什么重要"。

## 工作流

按顺序执行：

### Step 1: 识别主题与深度需求



* 解析用户请求，确定要学习的主题

* 解析受众参数（--age/--job/--grade），调整语言难度和类比方向

* 判断用户需要的深度：


  * `kpt` / 快速模式：≤ 5 个知识点，精简阵容

  * `kp11` / 默认模式：6-11 个知识点，标准阵容

  * `kpitch` / 完整模式：> 20 个知识点，启用 B 队

* 如需外部事实，先检索 / 读资料，确保知识点有来源、不编造；拿不准的标 "待考证"。

### Step 2: 盘点知识点与职能分类



* 列出该主题的**主流知识点**

* 每个先写好 "一句大白话解释 + 一个日常类比"

* 打上职能标签：地基 (守)/ 机制 (转)/ 思想 (想)/ 应用 (打)/ 结论 (进)

* 根据受众参数调整类比方向（--age 5 用玩具类比，--job manager 用商业类比）

### Step 3: 选择阵型（决策树）

按以下决策树选择阵型：



```
知识点数量？

├─ ≤ 5 个 → 精简阵（主教练 + 门将 + 能放的位置，不硬凑）

├─ 6-11 个 → 一套主力阵型

├─ 12-20 个 → 主力 + 替补席

└─ > 20 个 → 主力 + B 队

知识结构形态？

├─ 基础/机制/应用三层均衡 → 4-3-3

├─ 有一个非常清晰的主结论 → 4-2-3-1（单箭头+三前腰）

├─ 主结论+两个衍生结论 → 4-3-2-1（圣诞树）

├─ 理论 vs 实践两大板块 → 4-4-2

├─ 一个关键机制托底 → 4-1-4-1（单后腰）

├─ 机制/方法特别多 → 4-5-1 或 3-5-2

└─ 应用/案例非常多 → 3-4-3
```

**阵型选择权衡：**



* 4-3-3 最通用，但对 "单一主结论" 的主题表达力弱

* 4-2-3-1 适合 "目标导向" 主题，但中场防守（基础）可能薄弱

* 3-5-2 中场最厚，但后卫（基础）只有 3 人，不适合基础概念多的主题

### Step 4: 排位置



* 按 `references/positions.md` 的角色映射，把知识点放进对应位置：


  * 主教练 = 一句话核心思想

  * 门将 = 最底层基础

  * CB = 核心基础

  * LB/RB = 背景前置

  * CDM = 机制

  * CM = 方法 / 流程

  * AMD (CAM) = 核心思想 / 理论

  * LW/RW = 应用 / 案例

  * CF = 核心结论

  * SS = 衍生结论

  * 替补 = 进阶 / 边角

* **人不够 11 个就留空位**（= 可继续深挖的位置）

### Step 5: 写球员卡（ELI5 风格）



* 每个首发球员按下方【球员卡模板】用 ELI5 写法输出

* 替补 / B 队可更简

* 根据受众参数调整语言难度（--age 5 每句≤10 字，--age 25+ 可用术语）

* **质量标准：** 零背景读者能看懂、有日常类比、无未解释的术语

### Step 6: 画战术板



* 写出学习路径（球路，如 GK→CB→CDM→AMD→CF）

* 关键连线（谁和谁强相关）

* "三种输球方式"（最容易误解 / 出错的点）

### Step 7: 渲染阵型图



* 把阵容写成 JSON（结构见下方【阵型图 JSON Schema】）

* 运行 `python3 scripts/formation_diagram.py team.json output.svg`

* 校验输出 SVG 存在且非空

### Step 8: 交付与质量自查



* 按【输出模板】组织正文

* 阵型图用 present\_files 交付

* 完成 10 项质量自查清单

## 异常处理



| 情况         | 处理方式                                  |
| ---------- | ------------------------------------- |
| 知识点 < 3 个  | 提示用户主题太窄，建议扩展；只排 "主教练 + 门将 + 1 后卫"    |
| 知识点 > 50 个 | 自动拆分为多个子主题，每个子主题单独排阵型                 |
| 阵型图生成失败    | 降级为纯文本阵型图（ASCII 艺术），并提示用户检查 Python 环境 |
| 找不到主教练     | 如实说明 "本主题没有单一核心思想"，让门将承担统领角色          |
| 用户不满意阵型    | 提供 2-3 个备选阵型供选择，说明各阵型的表达差异            |

## 输入契约

用户输入格式：`[触发词] [主题] [可选参数]`



| 参数      | 类型     | 必填 | 说明                                     |
| ------- | ------ | -- | -------------------------------------- |
| 触发词     | string | 是  | kp11/kpt/kpitch/knowpitch              |
| 主题      | string | 是  | 要学习的知识领域 / 概念                          |
| 深度      | enum   | 否  | quick/standard/deep，默认由触发词决定           |
| 阵型      | string | 否  | 强制指定阵型（4-3-3/4-2-3-1 等）                |
| 语言      | string | 否  | 输出语言，默认中文                              |
| --age   | int    | 否  | 受众年龄（5/10/15/18/25+），调整语言难度            |
| --job   | string | 否  | 受众职业（manager/developer/student），调整类比方向 |
| --grade | string | 否  | 受众年级（5th/college/grad），调整专业深度          |

**受众适配规则：**



* `--age 5`：极简单词，玩具 / 动画类比，每句 ≤10 字

* `--age 10`：简单词汇，学校 / 游戏类比，每句 ≤15 字

* `--age 15`：日常词汇，生活 / 社交类比，正常句式

* `--age 25+`：专业词汇，职场 / 技术类比，可包含术语

* `--job manager`：商业框架，ROI / 风险 / 决策导向，避免代码

* `--job developer`：技术类比，代码 / 架构 / 性能导向

* `--job student`：学习类比，考试 / 笔记 / 课程导向

**输入示例：**



* `kp11 讲一下机器学习`（默认模式，4-3-3）

* `kpt 什么是通货膨胀`（快速模式，精简）

* `kpitch 深入讲解 React Hooks`（完整模式，B 队）

* `kp11 神经网络 --阵型 4-2-3-1`（指定阵型）

* `kp11 数据库索引 --age 5`（5 岁小孩能懂）

* `kp11 代码库结构 --job manager`（给经理解释，商务化）

* `kp11 Git 合并冲突 --grade 5th`（5 年级学生能懂）

## 球员卡模板（ELI5）

每个首发球员卡统一 4 行（默认 1–3 句；用户要求 "深入" 时可扩到 100–300 字）：



```
【位置代码｜知识点名】

\- 是什么：一句大白话（像对 5 岁小孩解释）

\- 像什么：一个日常类比（玩具/厨房/上学/手机……）

\- 传给谁：它和哪些队友联动（依赖/关系）

\- 为什么在这：一句话说明它为什么待在这个位置
```

## NEVER 清单（不要做这些）



1. **NEVER 硬凑 11 人** — 知识点不够时留空位，不要把边角料硬塞进首发。

* WHY：凑数的球员会稀释核心知识点，让阵型图失去重点。

* 错误示例：把 "历史背景" 这种边角料放进 CB 核心位置。

1. **NEVER 按重要性排序位置** — 位置由 "职能" 决定，不是由 "重要性" 决定。

* WHY：重要的知识点可能是 "应用"（LW/RW），不是 "基础"（CB）。

* 错误示例：把最重要的结论放 GK（门将应该是最底层基础）。

1. **NEVER 跳过阵型图生成** — 即使时间紧，也要生成 SVG。

* WHY：阵型图是本技能的核心差异化，纯文本输出和 ELI5 没有区别。

1. **NEVER 用专业术语解释专业术语** — 球员卡必须用大白话。

* WHY：违反 ELI5 内核，零背景读者看不懂。

* 错误示例："梯度下降是一种一阶迭代优化算法"（应该说 "一步步往山下走，找到最低点"）。

1. **NEVER 编造知识点** — 不确定的标 "待考证"，不要瞎编。

* WHY：错误知识比没有知识更有害。

1. **NEVER 把 B 队当主力** — B 队是扩展，不是第二套核心。

* WHY：B 队应该是 "想再多学一点" 的内容，不能和主力抢重点。

1. **NEVER 忽略 "三种输球方式"** — 战术板必须包含常见误解 / 错误。

* WHY：知道 "什么是错的" 和知道 "什么是对的" 同样重要。

1. **NEVER 在 description 里写 "I can" / "You can"** — 用第三人称。

* WHY：第一人称会破坏 Skill 的发现机制。

## 完整示例

### 示例 1：机器学习（kp11，4-2-3-1 + B 队）

**用户输入：** `kp11 讲一下机器学习`

**主教练：** 机器学习 = 让电脑从数据中自己找规律，而不是人写死规则

**首发阵容（4-2-3-1）：**

**门将 GK｜什么是 "从数据找规律"**



* 是什么：电脑看很多例子，自己总结出规律，不用人一条条写规则

* 像什么：小孩看了很多猫的照片，自己学会认猫，没人教他 "猫有四条腿 + 尾巴 + 耳朵"

* 传给谁：所有球员都基于这个基础

* 为什么在这：这是机器学习的定义，丢了就全崩

**后卫 CB｜特征 / 标签 / 训练集**



* 是什么：特征是输入的数据，标签是答案，训练集是学习用的题库

* 像什么：练习题（特征）+ 答案（标签）+ 一本题库（训练集）

* 传给谁：给 CDM（梯度下降）提供原料

* 为什么在这：没有数据就没法学习，这是地基

**后腰 CDM｜梯度下降**



* 是什么：一步步调整参数，让预测错误越来越小的优化方法

* 像什么：蒙眼下山，每步都往最陡的方向走，直到走到谷底

* 传给谁：给 CM（损失函数）提供优化方向

* 为什么在这：这是机器学习的核心机制，所有模型都靠它训练

**后腰 CDM｜损失函数**



* 是什么：衡量预测有多错的函数，错得越多分越高

* 像什么：考试扣分，错一题扣一分，目标是扣到 0 分

* 传给谁：和梯度下降强相关，告诉它 "往哪走能减少错误"

* 为什么在这：没有损失函数就不知道 "学对了没有"

**前腰 AMD｜监督学习**



* 是什么：给电脑看 "题目 + 答案"，让它学会从题目推答案

* 像什么：做练习题对答案，做多了就会考试了

* 传给谁：给 LW（分类 / 回归）提供理论基础

* 为什么在这：这是最常用的机器学习范式

**前腰 AMD｜无监督学习**



* 是什么：只给电脑看 "题目" 不给答案，让它自己找规律

* 像什么：给你一堆水果，不告诉你分类，你自己按颜色 / 形状分组

* 传给谁：给 RW（聚类 / 降维）提供理论基础

* 为什么在这：这是发现隐藏模式的核心思想

**前腰 AMD｜强化学习**



* 是什么：电脑通过 "试错 + 奖励" 学习，做对加分做错扣分

* 像什么：训练小狗，做对给零食，做错轻轻拍一下

* 传给谁：给 CF（预测）提供另一条路径

* 为什么在这：这是决策类问题的核心思想

**边锋 LW｜分类与回归**



* 是什么：分类是预测类别（猫 / 狗），回归是预测数值（房价）

* 像什么：分类是选择题，回归是填空题

* 传给谁：给 CF（预测）提供具体应用方法

* 为什么在这：这是监督学习最常见的应用场景

**边锋 RW｜聚类与降维**



* 是什么：聚类是自动分组，降维是把高维数据变简单

* 像什么：聚类是整理衣柜（按季节分），降维是把厚书浓缩成思维导图

* 传给谁：给 CF（预测）提供无监督应用

* 为什么在这：这是无监督学习的主要应用

**中锋 CF｜预测**



* 是什么：用训练好的模型对新数据做出判断

* 像什么：学会了知识点后去考试，对没见过的题作答
